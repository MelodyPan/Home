# Growth 改用 Google Drive 儲存

日期：2026-10-26

狀態：使用者已確認，程式已實作並通過替身與瀏覽器測試；真實帳號跨裝置驗收待實際登入。需求為「子網站 growth 的後端儲存方式跟 bookmarks 一樣」。

使用者已指定：growth 每個月一份紀錄檔，取代原先建議的每日一份。

## 目的與範圍

讓使用者以相同 Google 帳號，在電腦及手機讀寫同一份私人相簿。沿用相簿、孩子、孕期故事、照片、大頭貼、書封與成長數字的現有功能及資料欄位。

growth 的正式儲存方式統一為 Google Drive；本機服務與靜態網站均使用此方式。不再以本機 JSON 或照片目錄作為日常讀寫來源。既有本機原檔不刪除，也不自動上傳。私人資料及照片不加入公開建置。

## 方案

- 採用 bookmarks 現有的瀏覽器 Google 授權與 Drive 模式：符合使用者指定，沿用既有公開 Client ID 設定及可共用的授權程式。相簿使用獨立資料集與用途標記，避免混入書籤檔案。
- 保留本機與雲端兩種模式：增加設定與維護成本，不符合統一儲存方式的方向，因此不採用。
- 新建雲端後端或使用 Cloud Storage：需要另一套部署與憑證，不符合沿用 bookmarks 方式的需求，因此不採用。

## 具體行為

1. 右上角提供「登入」管理視窗，集中 Google Drive 連接、同步狀態、匯入與備份；沿用 bookmarks 的互動習慣。未連接時不載入私人相簿，也不能編輯。
2. 相簿存於私人 `MelodyHome` 資料夾內的獨立相簿區域。每個資料集依台灣時區的儲存月份，命名為 `growth-YYYY-MM.json`：同月更新同一份檔案，跨月有異動才建立新檔，保留前幾個月的檔案。每份保存當時完整相簿，包含歷年紀錄，不依故事日期拆分；修改舊故事也更新目前儲存月份的檔案。與書籤資料互不覆寫。
3. 照片另存私人 Drive 檔案，以相簿內部照片識別碼對應 Drive 檔案 ID；不將照片編碼塞入每月 JSON，也不每月複製照片。圖片透過授權讀取與瀏覽器暫時網址顯示，不建立公開分享連結。
4. 保留目前選照預覽與縮圖流程。先成功上傳照片，再提交引用它的相簿資料；重試儘量重用已確認成功的照片。第一版不自動刪除雲端照片，避免舊日期版本缺圖。
5. 日常保存以 Drive 版本檢查及條件式更新防止過期覆寫，沿用 bookmarks 的版本與衝突處理原則，將檔案週期改為每月。跨月並行建立也須避免重複檔案與靜默覆寫。衝突、離線或授權過期時停止新修改，保留目前分頁的草稿，提供重新連接、下載草稿與明確選擇版本。
6. 授權沿用 bookmarks 的目前分頁 sessionStorage 與閒置 10 分鐘策略；相簿內容和照片不自動持久化到瀏覽器儲存。登出與帳號切換會清除已載入的私人內容並釋放圖片暫時網址。

## 舊資料移轉與備份

提供一次性匯入流程，讓使用者選擇包含 `growth-data.json` 及 `growth-photos/` 的既有相簿資料夾。先驗證孩子、紀錄、照片關聯，顯示筆數與照片數，再由使用者啟動上傳。缺少照片時中止，不建立看似完整卻缺圖的相簿。

移轉只在所需照片全部上傳成功後提交相簿文件；中途失敗可重試，不覆蓋現有雲端相簿，也不刪除本機來源。已有多份雲端相簿時先讓使用者選取，不能任意挑選或靜默取代。

提供包含資料與照片的完整備份，以及失敗草稿下載；草稿中若仍有尚未上傳的照片，備份須一併包含或明確標示缺少項目，不能宣稱只下載 JSON 已保存全部照片。

## 修改與驗證範圍

新增 growth 專用 Drive 儲存與連接控制，調整前端的載入、保存、照片讀取和上傳介面，沿用既有畫面及驗證規則。更新本機靜態資源服務、公開建置、設定傳遞與文件，停用舊有日常本機資料 API。

驗證首次建立、資料集發現、照片讀寫、完整匯入、帳號隔離、授權過期、重試、同月更新、跨月保留、台灣時區月份邊界、修改歷史故事、跨月並行建立、雙裝置衝突及備份完整性；並執行 growth、bookmarks、Home 整合測試和公開建置檢查。

真實 Google 授權及跨裝置同步須另以實際帳號驗收，替身測試不代表真實驗收完成。

## 2026-10-30 使用者指定：孩子照片資料夾

照片存入私人 MelodyHome／成長相簿照片／孩子名字，資料夾用私有 child ID 標記辨識，更名不另建同一孩子的資料夾。同名孩子以 ID 前綴區分；照片由多位孩子共用時放入共同照片。既有照片於載入最新相簿時整理，新照片上傳、匯入及移動紀錄皆依此規則，沿用照片檔案 ID 與位元組，不變更每月 JSON 的位置。停止自動刪除舊圖片與空資料夾的原則維持。整理失敗可重試已確認的同一次寫入，避免重建紀錄或重複上傳照片。

## 2026-10-30 使用者指定：Drive 資料夾改用代號

本節取代孩子姓名作為照片資料夾名稱的規則：育銓對應 01，Baby 對應 02；其他孩子從 03 起配置未使用的數字代號。代號記於既有私人資料夾的 appProperties.code，依穩定 child ID 辨識；重新命名孩子不更改既有代號。舊姓名資料夾原地更名，不移除照片、不改檔案 ID。網站內仍顯示孩子姓名。
