# Bookmarks 個人 Google Drive 同步設計

日期：2026-10-26

後續使用者要求：載入既有資料後仍可再次匯入；匯入時確認筆數並以新版本取代目前資料集，保留舊版本。雲端資料集中存放於網站可存取的私人 `MelodyHome` 資料夾，重新連接時移動既有應用程式版本；不擴大 OAuth 權限讀取其他檔案。這兩項變更已由使用者直接要求並授權。

使用者進一步指定：網頁右上角保留「登入」按鈕，開啟管理視窗，將 Google Drive 連接、同步、再次匯入、匯出及備份集中於視窗內；主頁不顯示同步提示，也移除右上角的成長相簿入口。分類瀏覽及手機也須可開啟此按鈕。此為使用者直接指定的介面。

## 目的與已確認需求

使用者選擇 Google Drive，供自己在電腦及手機跨裝置存取、修改同一份書籤。保留現有書籤、分類、子分類、排序、收藏與匯出功能，資料維持私人。使用者進一步明確要求：bookmarks 一律使用雲端，不保留目前本機資料讀寫方式或模式切換。此設計僅處理 bookmarks，其他子網站不在此次變更範圍。

## 方案比較與選擇

- Google Drive＋瀏覽器 OAuth：使用者已選擇。沿用 JSON 檔案，靜態網站可直接呼叫 Drive API；需要處理授權過期及同步衝突。
- Google Cloud Storage＋後端：可集中處理存檔，但須設定雲端計費帳戶與部署後端；使用者已選擇 Drive。
- 維持本機檔案：使用者已明確排除，不保留作為執行模式。原始資料檔僅作首次手動匯入與備份來源，不刪除。

以下具體技術與介面取捨為實作建議，尚待使用者核准。雲端唯一儲存方式為使用者明確要求。

## 使用流程

1. 線上網站顯示「連接 Google Drive」。尚未授權時，不載入私人書籤。
2. 使用 Google Identity Services，請求 `drive.file` 存取權，僅操作網站建立或使用者透過 Picker 選取授權的檔案。不要求整個 Drive 存取權。
3. 第一次連接可建立空書籤資料，或選取本機匯出的 `bookmarks-data.txt`，驗證與預覽數量後由使用者按「匯入到 Google Drive」。不自動上傳現有本機資料。
4. 網站建立可見的私人資料檔，並透過 appProperties 標記用途。其他裝置用同一帳號及同一應用程式授權後，搜尋並開啟既有資料；搜尋結果不唯一時提供選擇，不直接另建空檔或任意覆蓋。
5. 修改後排隊自動儲存，顯示「儲存中／已同步／需要重新連接／同步失敗／資料衝突」。
6. 換裝置後登入並載入最新資料。回到分頁時，沒有草稿才可重新載入；有草稿時先進行版本判斷。
7. 保留「下載資料備份」。中斷連接時先處理未同步草稿，清除目前畫面中的私人資料與記憶體中的授權資訊。

## 儲存介面與現有程式的銜接

- 抽出資料存取介面：連接、讀取、寫入、重新載入、中斷連接；回傳已驗證文件、版本及能力資訊。
- bookmarks 僅經 Drive API 存取，沿用 `bookmark-file.js` 的 JSON 驗證及快照格式；移除本機資料載入、寫入、書籤快取回退與儲存模式切換。
- 移除對外提供 bookmarks 本機資料檔及本機存檔的路由，啟動時不再初始化本機書籤檔。既有資料檔保留，不自動搬移或刪除。
- 本機開發伺服器僅提供 bookmarks 網頁與公開設定；在 localhost 開啟也必須連接 Drive。Home 仍可為其他子網站提供原有服務。
- 未設定 OAuth Client ID 時顯示設定提示；未連接時顯示連接入口，皆不載入或允許修改本機書籤。不提供另一套 preview 儲存模式。
- `home.js` 的顯示及編輯邏輯使用同一個存取介面，移除對本機檔名、特定 API 的直接依賴。
- 共用 runtime 的變更須確保 growth 仍維持原有模式；若其資料根目錄沿用舊 bookmarks 設定，仍須維持相容，不因移除書籤本機讀寫而使相簿遺失資料位置。
- 移除依賴本機書籤檔的背景網址檢查啟動、輪詢及寫回流程。保留已儲存檢查結果的顯示與手動狀態編輯，不宣稱瀏覽器能檢查所有第三方網址。新增雲端網址檢查服務不包含在此次設計。
- 格狀／列表等裝置偏好留在瀏覽器；書籤本身、分類與收藏存入 Drive。

## 同步與避免資料遺失

- 序列化同一分頁的寫入；必要時合併尚未送出的快照，避免每次點擊產生多餘請求。
- 寫入前驗證文件並確認雲端版本。不能只先讀版本、再無條件覆寫，因為兩裝置仍可能同時通過檢查。
- 實作前必須查明並驗證選用 Drive 更新端點的條件式寫入行為與瀏覽器可取得的版本標頭。若無法提供可驗證的原子條件更新，採新增不可變快照、記錄父版本的方式，保留所有並行分支；不要以無條件覆寫作為替代。
- 衝突時停止自動儲存，保留分頁記憶體中的草稿及雲端版本，提供下載草稿、重新載入，以及使用者明確選擇後的取代流程。不自動合併刪除與分類異動。
- 若採不可變快照，資料發現以明確的書籤資料集識別碼、用途標記與父版本辨識；多個分支不能按時間靜默選取。保留目前 JSON 作為快照內容，額外中繼資料另存。第一版不自動刪除舊快照。
- 網路錯誤、API 限流或授權過期時，在目前分頁記憶體保留完整草稿及基準版本；不把完整書籤或草稿自動寫入 localStorage、IndexedDB 或本機檔案。重新授權相同帳號後先確認版本，再允許重試。
- 依使用者後續要求，授權 token 與最後操作時間暫存於目前分頁 sessionStorage，重新整理可恢復；操作延長閒置期限 10 分鐘，逾時清除登入與草稿。token 不寫進 localStorage、Git 或公開建置。未同步時提供手動下載備份及離開頁面警示；明確說明直接關閉分頁仍可能遺失未同步變更。
- 不提供離線資料載入或編輯；失去連線後保留目前畫面與未同步內容，暫停新異動，等待重連或手動匯出。瀏覽器僅可記住非資料性的顯示偏好。

## 設定與資料移轉

- 使用 Google Cloud 專案啟用 Drive API、設定 OAuth 同意畫面與 Web OAuth Client ID；註冊實際 HTTPS 網站及本機開發來源。
- 若加入既有 Drive 檔案選取，啟用 Picker 所需設定及限制來源的 API key。初版優先讓網站建立檔案並自行發現，以減少設定。
- Client ID 可用公開設定傳遞；瀏覽器不使用 client secret、服務帳號私鑰或 refresh token。
- 提供設定文件及公開設定範例。若沿用現有 Google 專案，先確認設定，不能因已有「Google 登入」就認為已有 Drive 授權。
- 正式發布與實際登入驗證需要使用者的 Google 專案設定及帳號操作；程式可先用替身測試驗證，但不能宣稱完成真實 Drive 同步。
- 公開建置仍不包含私人書籤；首次由使用者主動匯入現有資料。
- 暫維持目前公開首頁不列私人子網站的行為，線上 bookmarks 以原子路徑直接進入。

## 驗證與完成條件

- 自動測試：bookmarks 不再讀寫本機檔或回退至書籤快取、本機資料路由停用、啟動不建立書籤檔、Drive 資料驗證、同一資料集發現、重複資料集選擇、首次匯入、授權失敗／過期、網路失敗、分頁記憶體草稿重試及帳號隔離。
- 使用兩個獨立客戶端模擬同版本並行寫入，證明不會靜默遺失任一版本；驗證衝突後仍能匯出草稿。
- 建置驗證不包含私人資料與憑證；growth 的公開預覽及本機功能不受影響。
- 真實驗收：第一台裝置匯入、第二台讀取、兩端修改同步、過期重新授權，以及並行衝突恢復。
- 交付時區分「程式與測試完成」、「Google 設定完成」及「真實跨裝置驗證完成」。
