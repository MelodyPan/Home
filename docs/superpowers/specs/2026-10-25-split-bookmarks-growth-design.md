# 書籤與成長相簿拆站設計

## 目標

將目前 `apps/bookmarks/` 內的書籤及成長相簿整理為兩個子網站，保留既有畫面、功能與私人資料。此文件是待確認的建議，尚未修改網站程式。

## 建議結構

- `apps/bookmarks/`：`bookmarks.html`、書籤專用前端、服務及測試。
- `apps/growth/`：`growth.html`、成長相簿專用前端、儲存模組、參考資料、測試及文件。
- 共用的執行設定、主題與資料鎖依實際相依性放到共用位置；各站不依賴另一站的專用程式。
- 根目錄 `scripts/` 繼續負責 Home 的啟動、路由、建置與整體測試。

## 網址與入口

Home 首頁分成「書籤」及「成長相簿」兩張卡片。書籤使用 `/bookmarks/bookmarks.html`，相簿使用 `/growth/growth.html`；兩個目錄入口各導向自己的頁面，兩站都可返回 Home。

舊 `/bookmarks/growth.html` 轉址至新相簿網址。更新頁面間連結、相簿 API 及照片路徑，使新相簿可在自己的路徑使用完整功能。公開建置亦分成 `dist/bookmarks/` 與 `dist/growth/`，並支援 GitHub Pages 的專案路徑。

## 方案與取捨

建議採「程式及路由分站、共用 Home 服務」：符合目前 `npm start` 一次啟動所有網站的用法，且能保留原資料位置。

另開兩個服務及連接埠會增加啟動、健康檢查、停止及同來源驗證的維護成本，目前沒有此需求；僅在首頁分成兩個連結則無法完成使用者要求的 `apps` 目錄拆分。

## 資料與相容性

沿用 `.home-local.json` 指定的私人資料根目錄，不搬移、複製或重建既有書籤、孩子資料及照片。保留 ETag、寫入佇列與跨程序鎖保護。若需要新增相簿資料路徑設定，缺省值須相容目前的資料位置。

不變更頁面功能或視覺設計，不新增雲端服務，不推送或發布。保留工作區既有未提交變更。

## 驗證

執行受影響的既有書籤與相簿測試，補上拆站路由、舊網址轉址及公開建置的整合驗證。使用暫存資料測試相簿讀寫及照片路徑，確認兩站資源可載入且私人資料不會進入公開產物。

## 確認紀錄

使用者於 2026-10-25 回覆「好」，確認「共用 Home 啟動服務、兩個獨立子目錄與網址」的拆分方式。
