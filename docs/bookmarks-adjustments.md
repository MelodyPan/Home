# 書籤子網站調整總整理

整理日期：2026-10-30（台灣時間）

初次使用請先看 [使用指南](bookmarks-guide.md)，維護程式請看 [開發維護說明](bookmarks-development.md)。本文件保留歷次需求與發布紀錄，不需要從這裡開始學操作。

本文件整理這次持續調整的需求、目前行為與發布狀態。早期曾試作的「閒置 10 分鐘登出」及「10 小時內嘗試續期」已被後續需求取代，不能再當成目前的登入規則。

網站入口：[線上書籤網站](https://melodypan.github.io/Home/bookmarks/)。本機入口為 `http://127.0.0.1:4179/bookmarks/bookmarks.html`。

## 1. 資料一律放在 Google Drive

- 書籤以 Google Drive 為正式資料來源，供自己跨裝置使用。
- 資料放在私人 **MelodyHome** 資料夾，不需要公開分享資料夾或資料檔。
- 網站透過 Google OAuth 的 `drive.file` 權限，操作此應用程式有權存取的檔案。
- 每台裝置使用相同網站、相同 Google 專案及同一 Google 帳號，載入既有資料即可，不必每次重新匯入。
- 不提供原本的本機獨立編輯模式；新增可選擇的已同步書籤快取，離線只可瀏覽。本機 Node.js 服務是提供網頁與網址檢查功能，並不代表書籤改存本機。

### 每天一個檔案

檔名為 `bookmarks-YYYY-MM-DD.json`，日期依台灣時區 `Asia/Taipei` 計算，每個資料集每天一個檔案。

| 情況 | 儲存方式 |
| --- | --- |
| 同一天修改、收藏、分類或重查網址 | 更新當天同一個檔案 |
| 隔天有新的修改 | 建立新日期的檔案 |
| 隔天只有開啟網站、沒有修改 | 不為了日期改變而新增檔案 |
| 舊的日期時間命名版本 | 保留，不自動刪除 |

這項調整改掉了先前每次同步都產生一個新檔、Drive 檔案一直增加的問題。

### 同步、重試與跨裝置保護

- 約 600 毫秒內連續發生的操作會合併，減少上傳請求；內容沒有改變時不重複上傳。
- 寫入依序執行。已開始的上傳會完成，後續尚未開始的修改盡量合併為最新內容。
- 使用檔案版本與 `If-Match` 條件式更新，避免另一台裝置把較新的內容覆蓋掉。
- 先前「無法確認雲端版本」會阻擋儲存；現在當 Drive v3 未提供可讀取的 ETag 時，會改用 v2 回傳的 JSON `etag`，並透過同一版本 API 執行條件式寫入。
- 若仍無法取得版本資訊，會停止寫入並保留未同步草稿；不會無條件覆蓋雲端資料。
- 上傳結果不明時沿用原操作重試，避免重複建檔。跨日也有檔案 ID 預約機制，避免兩台裝置各建一份同日檔。
- 發生衝突時，由使用者選擇要採用的雲端版本或目前分頁草稿，不自動合併。

書籤內容與未同步草稿留在分頁記憶體，關閉或重新整理可能遺失未同步內容；遇到儲存失敗時，先在雲端管理下載未同步資料。

## 2. 登入、登出與 Google 授權效期

### 右上角按鈕

| 連接狀態 | 按鈕與操作 |
| --- | --- |
| 尚未連接 | 顯示「登入」，開啟 Google Drive 管理視窗 |
| 已連接 | 顯示「登出」，點擊即中斷網站與 Drive 的連接 |
| 已連接且要管理資料 | 使用「設定」開啟同步、匯入、匯出及備份功能 |

「登出」是中斷這個網站的連接、清除分頁授權與私人畫面，不是把整台裝置的 Google 帳號登出。有未同步草稿時，手動登出前會提示。

### 最終採用的效期規則

- 登入期限以 Google 實際回傳的 `expires_in` 為準。
- 使用者曾確認實際回傳為 **3599 秒，即 59 分 59 秒**；不是網站寫死每次都相同。
- 不再設定 10 小時續期窗口，也不再自動續期；操作不會延長期限。
- 憑證尚未到期時，F5 可使用目前分頁的 `sessionStorage` 恢復授權，再從 Drive 重新載入資料。
- 到期後中斷連接，需重新登入才能修改；同意暫存者可唯讀瀏覽已同步快取，目前分頁的未同步內容也可能被清除。
- 關閉分頁後不保證保留登入。`localStorage` 保存顯示偏好，以及使用者同意後的書籤快取與暫存選擇；主動登出會清除書籤快取。
- 雲端管理會顯示實際取得的 `expires_in` 與取得時間；舊授權若沒有這項紀錄，重新連接後才有實際數值。

### iPhone 取消登入後重試

使用者從主畫面捷徑開啟網站，在 Google 驗證畫面按關閉後，可能因為沒有收到取消通知而一直停在「連接中」。本機已補上返回頁面的恢復、可重點的登入按鈕、授權等待逾時與舊回應隔離。

詳細原因、1.5 秒返回等待、5 分鐘授權等待上限、測試及裝置驗收，見 [iPhone 登入恢復說明](bookmarks-iphone-login-recovery.md)。這些等待時間不會改變登入成功後的 Google 憑證效期。

## 3. 匯入、再次匯入、匯出與備份

- Google Drive 連接、帳號、同步狀態、重新同步、匯入、匯出 Chrome 書籤及 JSON 備份，集中在右上角的管理視窗。
- 第一次可匯入舊版 JSON 資料備份；`bookmarks-data.txt` 雖以 `.txt` 結尾，內容仍是 JSON。
- 已有書籤後，仍能從「設定 → 重新匯入」選檔，不必先刪除資料或重建資料集。
- 匯入前會顯示筆數並要求確認；確認後取代目前資料集內容，更新當日檔案，保留之前日期的檔案。
- 匯入後清除篩選，方便確認新的書籤內容。離線、同步未完成或存在衝突時，先處理同步狀態。
- 匯出 Chrome 書籤產生 HTML，供瀏覽器匯入；備份 JSON 則供本網站還原。
- 曾協助將使用者提供的 Chrome HTML 匯出檔重新整理為可還原資料；那是一次性的恢復作業。目前網頁的重新匯入功能仍以網站 JSON 備份為主，不直接接受 Chrome HTML。
- 私人恢復檔與網址檢查報告不應隨網站程式發布到公開 GitHub Pages。

## 4. 網址連線檢查與狀態

### 執行位置與檢查範圍

在「設定 → 資料管理 → 網址檢查與說明」視窗執行，可選全部書籤、目前篩選結果、已勾選項目、異常／未檢查項目；詳細卡片上的「重查」則檢查單筆。

| 使用環境 | 目前功能 |
| --- | --- |
| 電腦本機網站 | 可執行網址連線檢查，完成後同步 Google Drive |
| GitHub Pages 線上版 | 可瀏覽、編輯與同步 Drive，但目前沒有網址檢查後端，檢查按鈕停用 |

曾討論加設 Cloudflare 檢查服務，使用者決定不採用，維持目前流程。從本機完成檢查並同步後，線上版重新載入 Drive 資料，即可讀取更新的結果。

### 判斷規則

| 檢查結果 | 顯示狀態 |
| --- | --- |
| HTTP 200～299，且未辨識為登入頁 | 可連線 |
| HTTP 404／410 | 可能失效 |
| HTTP 401／403／407／429／451，或成功回應的最終網址為已辨識登入頁 | 登入／存取限制 |
| 逾時、DNS、憑證、連線問題或其他異常回應 | 待人工確認 |
| 內部、特殊、敏感或操作型網址 | 略過，歸入內部／特殊網址 |
| 尚無檢查紀錄 | 尚未檢查 |

「可連線」僅表示 HTTP 回應成功，不保證網頁內容仍與收藏時相同。存取限制或逾時不直接判定為失效；略過檢查也不表示網址無效。

### 檢查後自動存檔

- 同一網址只檢查一次，完成整批後將狀態與逐筆檢查時間合併到仍使用該網址的書籤。
- 自動同步至 `MelodyHome` 當日資料檔，不需要另按儲存。
- 局部重查不會更新「最後完整檢查」時間；全部檢查完成才更新這項時間。
- 手動標記的狀態仍優先保留；選「恢復自動檢查結果」後才顯示自動判斷。
- 關閉檢查視窗、取消或完成前連接條件改變時，中止尚未完成的檢查，不套用部分結果。
- 當結果已完成但同步失敗時，保留分頁草稿，供重試或下載備份。
- 內部網址、帳密、查詢參數、疑似私人識別碼路徑及登出／刪除等操作型網址會略過；檢查服務也會驗證 DNS 與每一跳重新導向。

## 5. 上方入口與下方分類的顯示差異

| 進入方式 | 顯示與操作 |
| --- | --- |
| 上方「所有書籤」，沒有搜尋關鍵字 | 圖示＋完整名稱的簡易連結，不顯示 checkbox 或批次工具 |
| 從「所有書籤」輸入關鍵字搜尋 | 顯示原本詳細卡片，保留編輯、收藏、刪除、重查、勾選與批次操作 |
| 清空「所有書籤」搜尋關鍵字 | 回到簡易連結，清除選取狀態 |
| 上方「常用收藏」 | 顯示常用收藏的簡易連結 |
| 下方用途分類 | 維持詳細卡片與原本操作功能 |

### 搜尋、篩選與排序

- 點「常用收藏」時，自動清除關鍵字、用途、原始資料夾、網址狀態、重複網址、第二層分類與已選項目，顯示完整常用收藏。
- 每次點「所有書籤」，預設使用網址排序，不將常用收藏排在前面。
- 「所有書籤」的排序獨立於其他分類，避免沿用另一個畫面的「收藏優先」。
- 在詳細搜尋結果中仍可透過排序選單調整；再次點「所有書籤」會回到網址排序。
- 格狀／清單偏好保留給詳細卡片；簡易連結使用自己的格狀排版。

### Checkbox 與批次操作

勾選框用來一次選取多筆書籤，供批次分類與「已勾選項目」網址檢查使用。一般開啟網站或加入常用收藏不需要勾選。

全選包含尚未展開、但符合目前篩選的結果。變更篩選會移除不再符合的選取；回到不提供勾選的簡易模式時清空選取。

## 6. 常用入口、分類與操作按鈕

- 首頁常用入口提供排序視窗，可用上移／下移調整；符合所選用途的全部收藏都顯示，順序會同步 Drive；已取消前 6 個上限，改用由上到下再往右的多欄清單。
- 首頁標題與「工作／生活」切換同排，預設工作，不顯示全部選項。用途切換只影響首頁收藏，不更改全站篩選或雲端資料。
- 常用入口與簡易連結的名稱完整顯示，寬度不足時換行，不再用省略號截斷。
- 左側「工作系統」點一下展開第二層分類，再點一次收合；收合不清除右側既有結果。程式開發分類採相同展開／收合行為。
- 第一層與第二層分類原有的管理、排序功能持續保留。
- 在「所有書籤」離開頂端時，右下角出現「上」按鈕；點擊回頂端後隱藏，其他分類與常用收藏不顯示此按鈕。
- 「復原刪除」已改成圓角外框按鈕，移除原本像文字連結的底線；首頁與清單位置均套用。

## 7. 版面簡化、重新整理與手機閱讀

### 已移除的畫面內容

- 主畫面原本的 Google Drive 連接／同步提示橫條；狀態改集中在雲端管理視窗。
- 右上角「成長相簿」連結。
- 側欄「← Home 首頁」按鈕。
- 「把喜歡的日常，好好收藏。」歡迎區塊。
- 「你的書籤，由你整理。」及快速入口旁的操作提示文字。
- 所有書籤及常用收藏標題下的裝飾說明。
- 底部宣傳文字、回到頂端按鈕與 footer 區塊；右下角浮動「上」按鈕保留。

### 減少重新整理閃動

- 首次恢復登入期間先遮住尚未初始化的畫面，避免先顯示「0 筆／登入」，再突然變成已連接狀態。
- 等待畫面保留書本圖示與「正在載入書籤…」；後來依需求移除下方兩個佔位區塊。
- 背景更新時保留目前資料；內容沒有改變時保留資料物件，避免重建卡片。
- 預留捲軸空間，減少內容變高後的水平跳動。
- 同意暫存時，F5 先呈現本機快取，再背景讀 Drive；未同意時維持原流程。雲端存檔成功後才替換本機快取。

### 手機卡片與排序選單

- 所有書籤／常用收藏簡易卡片固定一排兩個，長名稱換行；不改詳細卡片版面。
- 手機排序選單改為 13px，避免共用表單 16px 字級顯得特別大。此字級調整納入本次更新。

### 網站圖示

- 首頁清單只顯示成功讀取的網站圖示，讀不到就不顯示，不留文字備援。
- 簡易卡片固定顯示分類圖示，網站圖示成功後在旁邊並列；失敗只保留分類圖示。此雙圖示規則納入本次更新。
- ChatGPT 與 Gemini 官方圖示保存為網站資源；其他網站仍可嘗試根目錄 favicon.ico。詳細卡片原有的文字備援不變。

### 手機底部提示文字

原本底部提示框的灰字與紫色背景對比不足。本機已改成白字、14px、字重 500；手機寬度驗證對比為 6.30:1，並確認提示框不超出畫面。此項納入 2026-10-29 本輪發布。

## 8. 瀏覽器圖示與 iPhone 主畫面捷徑

- 瀏覽器分頁使用紫色書本 SVG favicon。
- iPhone「加入主畫面」另外使用網站既有的 Melody logo，設定為：

```html
<link rel="apple-touch-icon" href="../images/logo.png">
```

相對路徑對應 GitHub 專案的 `/Home/images/logo.png`，建置會一併發布圖片。`href="/"` 是網站根網址，不是圖示圖片路徑。

這次直接沿用原本的正方形 PNG，沒有重畫 logo，也沒有另製 180×180 圖片。主畫面舊捷徑可能保留先前圖示，上線後刪除舊捷徑，再從 Safari 重新加入主畫面。
