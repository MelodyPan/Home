# Home 子系統與雲端存檔整理草案

日期：2026-10-25。使用者希望 GitHub 上的網頁可以新增照片、儲存紀錄；尚未選定雲端供應商，已明確不採用 Supabase。Home 本機整合與公開預覽建置已完成，詳見 [整合操作說明](home-integration.md)；尚未上傳或發布網站。下列為原始規劃與待接雲端項目。

## 目前確認的狀態

- 本機 Home 專案位於 `C:/Users/D078/source/repos/Home`，Git 遠端為 `MelodyPan/Home`。
- Home 的 `.github/workflows/static.yml` 已改為先測試與建置，再於 main 推送時只發布 dist。
- Home 的 `index.html` 有尚未提交的修改，整合時須保留並在既有修改上調整。
- 子系統程式已整合至 Home/apps/bookmarks，資料仍留原目錄；前端已支援子路徑與預覽模式。
- `bookmarks.html` 目前包含原始書籤資料，不能直接當作不含個人資訊的公開發布檔。
- 既有相簿包含本機照片 ID；不能只把 JSON 複製到線上，就認為照片也已完成搬移。

## 不依賴供應商的整理方向

1. 保留 Home 首頁及既有子系統，將 Bookmarks 程式放入 `apps/bookmarks/`。
2. 將靜態網頁、CSS、JS、公共圖表參考資料，與 Node 本機服務分開。
3. 新增資料存取介面，讓書籤與相簿透過同一個介面選擇本機／雲端儲存；不以全域覆寫 fetch 攔截請求。
4. 網址及資源支援 `/Home/bookmarks/` 子路徑，從頁面位置組合資源及 API 設定，避免寫死主網站根目錄或本機連接埠。
5. GitHub 的公開建置只使用空資料或明確的示範資料；個人書籤、孩子資料、照片、備份及原始私人匯出檔不納入發布。
6. 改為只發布 `dist/`，並檢查打包結果沒有個人資料或管理金鑰。

## 雲端功能必須完成的項目

- 登入與登出；尚未登入時不能讀取私人紀錄或照片。
- 資料依使用者識別碼隔離，服務端規則驗證所有權，不能只靠前端篩選。
- 照片採私人儲存，讀取受登入身分約束；不把長效公開照片連結或管理金鑰寫入 GitHub。
- 保留相簿、孩子、書封、封面、照片排序、孕期紀錄與成長量測的既有格式及功能。
- 書籤也需要雲端保存；網址檢查、停止本機服務等本機專屬功能依模式調整。
- 保留併發版本衝突檢查、失敗後保留草稿與重試，避免不同裝置互相覆蓋。
- 照片大小與格式限制同時在前端及雲端儲存規則執行。
- 本機資料搬移須有明確匯入流程、照片搬移與完成驗證，不自動上傳現有個人資料。
