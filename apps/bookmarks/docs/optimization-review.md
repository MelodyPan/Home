## 建議實作批次

1. **先提升日常整理效率**：名稱／網址編輯、批次分類、全畫面存檔提示。
2. **再改善資料品質**：重複網址整理、檢查原因細分與局部重試。
3. **完成資料搬移流程**：JSON 還原與 Chrome HTML 匯入預覽。
4. **依使用需求擴充**：常用入口排序、標籤、備註與最近使用。

## 開發時應保留的規則

- 「中榮」原始資料夾的書籤維持工作用途。
- 名稱排序或收藏排序仍在搜尋的工作系統優先分組內生效。
- 刪除子分類不刪除書籤；「未分類」維持最後。
- 手動狀態與自動檢查結果分開保存；網址變更須明確處理原有狀態。
- 寫入維持版本衝突檢查及備份，新增欄位須相容既有 JSON。
- `.bak` 目前只保存上次寫入前的版本；如需多次還原，可另設有數量限制的歷史備份。

## 其他觀察

- 啟動器等待服務就緒的時間固定，先前曾出現啟動器報失敗但服務稍後已正常啟動的情況。可延長等待、顯示啟動階段，並保留診斷資訊；仍需在實際啟動環境重現與驗證。
- 每次輸入搜尋都重算資料夾、統計及卡片。現有數量可先維持；資料明顯增加或實測輸入延遲時，再做快取、搜尋延遲合併或局部重繪。
- 有一筆待確認原因含替代字元，建議日後加入資料文字編碼檢查，不直接改寫使用者資料。
- 手機看不到本機截圖是圖片傳送與裝置存取問題；增加網頁功能不會讓手機自動取得電腦本機檔案。跨裝置瀏覽若有需要，應另行規劃存取與資料同步方式。
